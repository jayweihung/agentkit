# 規則、技能、MCP、外掛的版本：看得到、管得住

2026-11-21，jay 提的：「這些 skill、rule、plugin、mcp 可不可以有版本」、「agent 視窗也有版本，這樣我才知道哪些是用舊的或新的」、「你可以規劃一下怎麼控制跟規劃」。

## 為什麼要做

jay 同時開很多 agent、好幾台機器（Mac、伺服器、公司、Windows），規則和技能常常在改。現在看不出：

- 某個 agent 讀到的是不是最新的那份；
- 哪台機器還沒同步；
- 收來的技能是原作者哪一版、新版改了什麼；
- 改壞了要怎麼退回、怎麼先讓某台不要跟著換。

目標：每一項都有一個看得懂的版本；任何 agent、任何機器，一眼看出用的是新的還是舊的、為什麼舊、怎麼變新；改壞了能退回。

## 目標、不做的、不能變成的

- 目標
  - 每一項（規則、技能、MCP、外掛）有版本：倉庫（Kit 面板）和 agent 視窗都顯示。
  - agent 視窗標出「舊版」，並說是哪一種舊、要做什麼才會變新。
  - 每一項看得到歷史：每一版的日期、改了什麼（commit 訊息）、前後差在哪。
  - 控制：退回某一版；讓某台機器先固定在某一版（不跟著更新）；收來的先看差異再收。
- 不做
  - 不要求寫的人手動編版本號（1.2、1.3）。
  - 不做每個 agent 各自鎖版本（agent 讀的是機器上的那份；要不同版本用 `kit run` 的 agent 定義，那是另一件事）。
  - 不改 root 的核准流程（`kit approve`），只把它的版本顯示出來。
- 不能變成的
  - 一堆版本數字但看不出新舊：畫面上主要是「最新」或「舊版＋原因」，版本號是次要的小字。
  - 只有 Mac 能用：Windows 的 kit（kit.ps1）和 Herdr 都要一樣能看、能控制。
  - 退回或固定之後忘了：被固定、被退回的都要一直標著，直到解除。

## 版本是什麼

用過的三種做法（2026-11-21 跟 jay 討論，jay 交給我決定）：

| 做法 | 好處 | 為什麼不選 |
|---|---|---|
| **A. 最後修改的日期＋內容指紋**（選這個） | kit 自己算，四種都適用，寫的人什麼都不用做 | — |
| B. 版本號（1.2、1.3） | 直觀 | 要有人記得加；收來的大多沒有，最後混兩套 |
| C. git commit | 自己寫的很準 | 裝到各機器上的副本、MCP 設定對不上 commit，還是要比內容 |

一項的版本＝兩個東西：

- **指紋**：這一項的內容算出來的短碼（技能、外掛：整個資料夾；規則：那個檔；MCP：那份設定）。內容一樣，指紋就一樣，不管在哪台、哪個來源。kit 安裝時本來就在 `state.tsv` 記一個 cksum，改成存這個指紋。
- **「最新」是哪一份**（我的決定）：來源遠端上次 `kit sync` 抓到的最新 commit（`origin/<分支>`），不是這台 clone 的工作目錄。這樣「這台的 clone 還沒 pull」也算「這台還沒同步」。Claude 的規則是 `@` 直接指到 clone 裡的檔，所以它的「裝的」就是 clone 現在的內容；clone 落後遠端，就是舊。
- **顯示的名字**：來源 repo 裡最後一次改到這一項的 commit 日期，例如「11/21 版」。同一天改好幾次：「11/21 版（3）」。滑鼠停上去：完整日期、commit 訊息、指紋。來源裡改了還沒 commit 的：「改了還沒送出」。

收來的另外有「原作者的版本」：`third_party.lock` 裡的 commit 和收的日期；原作者現在的 commit 用既有的 `kit outdated` 問。

## 三種「舊」

agent 視窗每一列跟最新版比，不一樣就標「舊版」，並寫是哪一種：

1. **這台還沒同步**：機器上裝的指紋 ≠ 來源最新的指紋。做法：按「同步」（或等它自己同步：Claude、Codex、omp 開新對話時會背景 `kit sync`）。
2. **這次對話讀的是舊的**：機器上已經是新的，但這個 agent 是在那一項換版之前開始的。kit 記下每一項在這台「換上這個指紋的時間」，跟 agent 行程的開始時間比。做法：開新對話；Claude 的技能、外掛也可以 `/reload-plugins`（Kit 1.9 已經會送）；規則一定要新對話。
3. **固定在舊版**：這台被固定了（下面「控制」）。寫固定在哪一版、誰固定的、為什麼。

收來的：原作者有新版時，倉庫那一列寫「原作者有新版 11/25」（這不算 agent 舊，因為 kit 還沒收進來）。

root 這類只用核准版本的帳號：用的是核准的 commit，跟來源最新的不同時標「等核准」，不是「舊版」；版本從 root 每 10 分鐘寫的清單讀（Kit 1.11 已經在讀 `/var/lib/kit-root-view/list.json`）。

## 控制

| 想做的 | 怎麼做 | 影響誰 |
|---|---|---|
| 改壞了，全部退回上一版 | 倉庫那一項的歷史裡按「退回這一版」：kit 在來源做一個 commit，把這一項的內容換回那一版（不是 git revert 整個 commit，只動這一項），照來源平常的方式送出（直接推或 PR） | 每台、每個帳號（root 要再核准） |
| 先讓某一台不要跟著換（例如公司那台先別動） | `kit hold <種類> <名字> [版本]`：寫進那台的 `machine.yaml`（`held:`），`kit sync` 不換它；`kit release …` 解除。Kit 面板的「各機器」頁可以按 | 只有那台那個帳號 |
| 收來的先看再收 | 「收新版」前顯示每一項從哪版到哪版、差異（檔案的增刪改），可以只收某幾項 | 收進的來源 |
| 看某一項在每台是哪版 | 倉庫那一項的詳細頁：每台機器一行（版本、新或舊、固定了沒）；資料來自每台的 `kit list --json`（別台用 Herdr 的連線問，跟現在一樣） | 只看 |

固定和退回都要一直顯示：倉庫和 agent 視窗那一列都有「固定在 11/18 版」「11/21 退回到 11/18 版」，直到解除或有新版取代。

## kit 要多給的（kit api 1.14）

`kit list --json` 每一項多：

```json
"version": {"id": "a1b2c3d4", "date": "2026-11-21", "n": 1, "commit": "<40 字>", "message": "…", "dirty": false},
"installed": {"claude": {"id": "a1b2c3d4", "at": 1763690000}, "codex": {"id": "…", "at": …}, "omp": null},
"held": null
```

- `version`：來源最新的。`dirty`：來源有還沒 commit 的改動（這時 `id` 是現在內容的指紋，`commit` 是 null）。
- `installed`：這台每個工具裝的那份（我的決定：分工具記，`state.tsv` 本來就分開記外掛和規則），沒裝的工具是 null。`at`：換上這個指紋的時間。`held`：固定的版本（`{"id", "by", "why", "at"}`）或 null。
- 有 `--dir` 時，資料夾自己的那份（`kit add --dir`、`kit place`）也算「裝的」：在那個資料夾開的 agent 讀的是它，`installed` 用那份（我的決定）。`kit run` 帶的：那份在啟動時給，比的是啟動時間。
- 有 `--pid`（和 `--tool`）時，每一項再多 `"loaded": "new" | "old" | "unknown"`，照種類算（我的決定，因為各種讀的時間不一樣）：
  - 規則、MCP、外掛：對話開始時就讀（MCP 是那時啟動的程式）→ agent 開始的時間早於那個工具的 `installed.at` 就是舊。
  - 技能：開始時只讀名字和說明，內容是用到時才讀 → 這次對話用過（`kit used`），而且用的時間早於 `installed.at` 才算舊；沒用過的寫「新」（用到時會讀到新的），說明文字是舊的不另外標。

新指令：

- `kit history <種類> <名字> [--json]`：這一項的每一版（從來源的 git log 只看這一項的路徑），每版的日期、訊息、指紋、作者。
- `kit diff <種類> <名字> <版本> [<版本>]`：兩版的差異。
- `kit revert <種類> <名字> <版本> [--to 來源]`：上面的「退回」。
- `kit hold` / `kit release`：上面的「固定」。

Windows 的 kit.ps1 一起做，欄位一樣。

## Herdr 的 Kit mod 要多的

- 倉庫每一列：版本小字（「11/21 版」），有固定、退回、原作者新版就標出來。點進去的詳細頁多「歷史」和「各機器」兩塊，歷史每版可以看差異、退回。
- agent 視窗每一列：版本小字；舊版的列有標記和原因、要做什麼（按鈕：同步、清空重來；規則寫「開新對話才會讀到」）。最上面一行總結：「全部最新」或「3 項舊版」。
- 「各機器」頁：每台一行，幾項舊、幾項固定；點進去看是哪些。
- kit 太舊（api < 1.11）的機器：不顯示版本，寫「那台的 kit 太舊，更新後才看得到版本」。

## 分三步做

1. **看得到**：kit 給 `version`、`installed`、`loaded`（api 1.14；Kit mod 看到 api < 1.14 就寫「那台的 kit 太舊」）；Kit mod 在倉庫和 agent 視窗顯示版本和舊版標記。（jay 這次要的就是這步；做完先用一陣子再決定後兩步的細節。）
2. **歷史**：`kit history`、`kit diff`；詳細頁的歷史和各機器。
3. **控制**：`kit revert`、`kit hold`／`release`；收新版的前後差異。

每一步：kit 的測試（unix 和 Windows）、Kit mod 在 Mac 上看過、Windows 上看過，再推。

## 留給做的人決定

- 指紋的算法（cksum 還是 sha 的前 8 碼）、怎麼把一個資料夾算成一個指紋（檔名排序、忽略 `.DS_Store` 這類）。
- `installed.at` 存在 `state.tsv` 的哪一欄、舊的 `state.tsv` 怎麼升級。
- agent 行程的開始時間怎麼拿（Mac／Linux `ps -o lstart`、Windows 的程序建立時間）。
- 畫面的細節（小字放哪、顏色），照 Kit mod 現在的樣子。
